## 어떻게 도나

1. 예약(Claude 쪽 scheduled task)이 정해진 시각에 **배차 세션**('EDIT H 배차')을 깨운다.
2. 배차 세션은 `create_session` 으로 **작업 세션**을 하나 만들고 끝낸다 — 저장소 main 연결·main 푸시 권한·자동 실행 권한·모델을 지정한다.
3. 작업 세션은 아래 표의 지시 파일을 읽고 그대로 한다. 기억은 없다 — 절차는 모두 저장소 문서에 있다.

예약이 직접 새 세션을 만드는 방식(create_new_session_on_fire)은 쓰지 않는다 — 그렇게 뜬 세션은 저장소가 붙지 않아 푸시를 못 하고,
힉스필드·GitHub 도구도 없다(2026-11-12 시험 T2·T3). `create_session` 으로 만든 세션은 저장소·푸시·도구가 모두 있고 자동 점검도 통과했다(시험 T1).

작업 세션의 모델은 그동안 루틴이 돌던 설정(claude-opus-5-5)으로 지정한다. 배차 세션은 가벼운 모델로 '세션 만들기'만 하고, 대화가 몇 달 쌓여 길어지면 새로 만든다.
끝에서 끝까지 확인(2026-11-12 14:35): 예약 → 배차 → 작업 세션 → `selfcheck.md` 대로 main 에 한 줄 푸시까지 사람 없이 1분.
같은 구조에서도 **저장소 문서에 근거가 없는 낯선 지시**(시험용 브랜치 푸시)는 작업 세션이 "해도 되나요?"라고 묻고 멈췄다 — 그래서 할 일은 반드시 지시 파일에 적는다.

## 작업 세션이 지킬 것 (모든 루틴 공통)

- 지켜보는 사람이 없다. 질문하지 말고 끝까지 한다. 막히면 이유를 마지막 답에 적고 끝낸다.
- 처음에 한 줄씩: `git fetch origin main` → `git checkout main` → `git pull --ff-only origin main`.
- 저장소 맨 위 `AGENTS.md` 3절(꼭 지킬 것)을 지킨다 — 비밀값·구독자 주소 금지, 발송·게시 경로 머지 시간, 강제 푸시 금지, 커밋·PR 에 모델 이름 금지.
- 커밋 메시지 끝의 공동 작성 줄은 `Co-Authored-By: Claude <noreply@anthropic.com>` 로 쓴다 — **모델 이름·버전을 붙이지 않는다**(AGENTS.md 3절). PR 제목·본문도 같다.
- PR 이 필요한 루틴의 작업 브랜치는 **고정 이름을 다시 쓴다**: `routine/improve` · `routine/reel` · `routine/weekly` · `routine/check`.
  `git checkout -B <이름> origin/main` 으로 시작해 커밋하고 일반 푸시한다(강제 푸시 금지 — 지난 PR 이 머지돼 있으면 그대로 올라간다).
  푸시가 거절되면 머지되지 않은 지난 PR 이 남은 것이니 그 PR 을 먼저 확인하고, 새로 올릴 땐 `<이름>-{날짜}` 를 쓴다.
  (이 환경에서는 원격 브랜치를 지울 수 없어, 날마다 새 이름을 쓰면 브랜치가 쌓인다.)
- 예약 작업(scheduled task)을 만들거나 바꾸지 않는다. 다른 세션을 만들지 않는다(자신을 다시 깨우는 send_later 는 된다).
- 운영자에게 꼭 알려야 하는 일(릴스 게시 완료, 발행 실패, 사람 손이 필요한 오류)은 **PushNotification 한 줄**로 알린다. 평소 보고는 마지막 답으로만.
- 마지막 답은 한국어로 짧게, 첫 줄에 결과.
- 운영자만 할 수 있는 일(토큰·계정·비용)은 하지 말고 `automation/OWNER_TODO.md` 에 제안만 적는다.

## 고칠 때

- 루틴이 하는 일을 바꾸려면 **지시 파일을 고친다**(PR). 예약 지시문은 '어느 파일을 읽어라'만 담고 있어 건드릴 일이 거의 없다.
- 시각·모델을 바꾸거나 되돌리려면 운영 대화('뉴스레터 및 카드뉴스 자동화')나 새 대화에서 Claude 에게 말한다.
  예전 방식(한 대화에서 계속 돌기)의 지시문은 이 폴더의 지시 파일과 같은 내용이다(2026-11-12 옮김).
- 기존 제작 세션 예약(07:40, 길게 이어진 세션)은 전환 첫날(11/13) 하루만 보험으로 같이 돌린다 — 둘 다 제작하고 먼저 올린 쪽이 나가며,
  늦은 쪽은 푸시 직전에 `origin/main:{날짜}.html` 을 보고 멈춘다. 새 방식이 제때 올리면 그날 끈다.
