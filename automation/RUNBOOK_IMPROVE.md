## 1. 오늘 고칠 거리 모으기 (10분)

우선순위 순서:
1. **어제·오늘 발행 흐름에서 실패한 것** — `automation/alerts/{어제,오늘}.json`, 지난 24시간 GitHub Actions 실패 실행
   (`gh api repos/vetnam555-del/edit-h-archive/actions/runs?status=failure&per_page=10`), `automation/sent/`·`ig_posted/` 빠짐.
2. **`automation/learnings.md` '시스템 개선 요청'** — 22:00 회고가 적은 것(오래된 것부터).
3. **실험 판정일** — `automation/references.md` '지금 시험 중'에서 기간이 끝난 실험. 성과표 줄을 읽고 유지·되돌림을 정해
   `learnings.md` 원칙/가설로 옮긴다(되돌림 스위치는 references.md 에 적혀 있다).
4. **빌드 경고가 매일 반복되는 것** — 최근 제작 보고·`↘` 경고(카드 자동 축소, 문장 점검, 한 줄 뉴스 부족 등)에서 같은 것이 3일 이상이면
   규칙·템플릿·검사를 고친다.
5. 위가 비어 있으면 `references.md` '다음 실험 후보'에서 **지금 시험 중인 실험과 같은 지표를 건드리지 않는** 작은 것 하나를 준비한다
   (시작일을 다음 실험이 끝난 뒤로 잡는다 — 한 번에 한 변수).

고를 때: (독자·발행에 미치는 크기) × (확실함) ÷ (위험). **하루 PR 하나**, 고치는 건 1~2건.
재현이 안 되거나 원인이 사람 몫(토큰·계정·비용)이면 고치지 말고 `OWNER_TODO.md` 에 올리거나 보고에 적는다.

## 2. 고치기

- 먼저 재현한다(실패 로그·스냅숏·임시 복사본 빌드). 원인을 한 줄로 적을 수 있을 때만 고친다.
- 변경은 최소로. 발행 산출물(지난 호 html·카드·content)은 다시 만들지 않는다 — 과거 호는 기록이다.
- 새 동작에 날짜 스위치가 필요하면(편집 방향·게시 방식) `config.json` 이나 상수에 시작일을 두고 references.md '지금 시험 중'에 줄을 더한다.

## 3. 검증 → PR → 머지

```bash
python3 automation/selftest.py            # 반드시 '✓ 자동 점검 통과'. 글이 달라졌으면 의도한 변경인지 확인해 PR 에 적는다
```

1. 커밋(영어 메시지, 모델 이름 쓰지 않기) → `git push -u origin claude/clever-wright-u30ihp`
2. PR 을 draft 로 만들고 → ready 로 바꿔 Codex 리뷰를 받는다. PR 설명: 무엇을·왜(근거 숫자/날짜)·확인한 것.
3. Codex 지적은 검증해서 고치거나 이유를 답하고 스레드를 닫는다. **GitHub Actions 'EDIT H selftest' 가 초록**이어야 머지한다.
4. merge 방식으로 머지 → 브랜치를 main 으로 fast-forward 해 푸시.
5. 발송·게시 경로(send_newsletter·post_instagram·post_threads·워크플로)를 바꾸는 머지는 **06:30~09:00, 18:00~20:00 KST 에는 하지 않는다.**

## 하지 않는 것

- 비밀값(토큰·비밀번호)을 출력·커밋하지 않는다. 구독자 주소를 저장소에 넣지 않는다. Design M 키트 파일·프롬프트를 옮기지 않는다.
- 돈이 드는 서비스 가입·광고 집행, 발송 시각 변경, 공개 호스팅 방식 변경, 구독자 명단 변경 — 제안만 하고 `OWNER_TODO.md` 에 올린다.
- 테스트·점검을 끄거나 건너뛰어 초록을 만들지 않는다. 강제 푸시하지 않는다.
- 하루에 PR 을 여러 개 열지 않는다(검토·판정이 섞인다).
