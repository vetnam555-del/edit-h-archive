# EDIT H 데일리 발행 런북 (클라우드 루틴용)

이 문서는 매 영업일 **08:00 KST**에 시작하는 Claude 클라우드 루틴이 그대로 따라 하는 절차다.
목표는 **08:45 전에 main 에 푸시**하는 것. 메일 발송은 GitHub Actions 가 **09:00**에 한다
(`.github/workflows/send-newsletter.yml`). 늦게 푸시해도 푸시 즉시 발송되므로, 서두르다 품질을 버리지 않는다.

> **권한** — 이 루틴은 사용자가 승인한 자동 발행 작업이다. 브랜치를 만들거나 PR 을 열지 말고
> **main 브랜치에 직접 커밋·푸시**한다. 발행 산출물(아래 6단계 목록) 외의 파일은 건드리지 않는다.

---

## 0. 준비

```bash
cd <저장소>            # vetnam555-del/edit-h-archive
git checkout main && git pull --ff-only origin main
python3 automation/check_today.py              # 오늘(KST). 리허설·재빌드는 날짜 인자: check_today.py 2026-09-28
```

- `publish: false` 면 `skip_reason` 을 한 줄로 보고하고 **끝낸다**(주말·공휴일·이미 발행).
- `warnings` 가 있으면 최종 보고에 그대로 적는다(예: 다음 해 공휴일 미등록).
- `next_vol`, `recent_item_titles`(최근 5호에서 다룬 주제), `recent_issues` 의 **마지막 발행일**을 메모해 둔다.

## 1. 소스 수집 (최대 35분)

### 1-1. 1순위: 안장출근길

`automation/config.json` 의 `primary_source.url`(네이버 프리미엄콘텐츠 '안장출근길')을 WebFetch 로 연다.

- 오늘 날짜 글이 보이면 **제목·목차·무료 미리보기**에서 주제 후보를 뽑는다.
- 유료 벽·로그인·네트워크 차단(EGRESS_BLOCKED 등)이면 WebSearch 로 `안장출근길 {M월 D일}` 을 한 번 찾아보고,
  그래도 없으면 1-2 로 넘어간다. 여기서 시간을 5분 넘게 쓰지 않는다.
- **안장출근길은 '무엇을 다룰지' 고르는 단서일 뿐이다.** 본문 문장을 옮기지 않고, 출처로 표기하지 않는다.
  모든 사실은 1-3 에서 원 기사로 확인하고 **원 기사를 출처로** 단다.
- 안장출근길에서 주제를 3개 이상 가져왔으면 JSON 의 `source_mode` 를 `"anjang"`, 일부면 `"mixed"`, 못 썼으면 `"fallback"`.

### 1-2. 보강·대체 소스 (안장출근길이 없거나 10개가 안 될 때)

WebSearch 로 **직전 발행일 이후**(주말·연휴 포함, `recent_issues` 의 마지막 날짜 다음 날부터)의 뉴스를 카테고리별로 찾는다.
평일 연속 발행이면 사실상 최근 36시간이고, 월요일·연휴 뒤 첫 호는 그 기간 전체가 대상이다(가장 최근 것 우선).
검색어에 날짜(`9월 23일`, `2026`)와 주제를 같이 넣고, 연휴 뒤엔 날짜를 바꿔 가며 여러 번 찾는다.

| 카테고리 | 검색 예시 |
|---|---|
| 유통/커머스 | `유통업계 {날짜}`, `쿠팡 네이버 컬리 {날짜}`, `편의점 백화점 매출 {월}` |
| 플랫폼/AI | `AI 쇼핑 에이전트 {날짜}`, `오픈AI 구글 메타 발표 {날짜}` |
| 광고/브랜드 | `브랜드 캠페인 성과 {날짜}`, `광고 도달률 조회수 {날짜}` |
| 소비/트렌드 | `소비자 조사 {월}`, `MZ 트렌드 {날짜}`, 시즌 이슈(명절·연휴·시즌 세일) |
| 규제/신뢰 | `공정위 {날짜}`, `개인정보 유출 {날짜}`, `플랫폼 규제 법안 {날짜}` |
| 콘텐츠/SNS | `인스타그램 유튜브 틱톡 새 기능 {월}`, `숏폼 커머스 {날짜}` |

믿을 만한 출처: 통신사·종합/경제지(연합뉴스, 뉴스1, 뉴시스, 한국경제, 매일경제, 머니투데이, 서울경제, 아주경제, 파이낸셜뉴스, 헤럴드경제, 이데일리),
IT·산업 전문지(전자신문, ZDNet Korea, 디지털데일리, AI타임스, 블로터), 정부 보도자료(korea.kr),
기업 공식 뉴스룸·블로그(국내외 모두. `name` 은 `Meta 뉴스룸`, `YouTube 블로그`처럼 '회사 + 채널'로 적는다).
블로그·커뮤니티·보도자료 재가공 사이트는 **출처로 쓰지 않는다**(단서로만).

### 1-3. 사실 확인 규칙 (가장 중요)

- **날짜 함정**: 검색 요약은 작년 기사를 올해 것처럼 말할 때가 있다. URL 의 날짜
  (`/2026/09/22/`, `article/2026092...`, `view/20260923...`)나 기사 표기일로 **발행일을 반드시 확인**한다.
  (실제 사례: 2025-09-23 기사 `hankyung.com/article/2025092329741` 가 '2026년 9월 23일'로 요약됨,
  2026-04 무신사 메가스토어 기사가 '24일 오픈'으로 요약됨)
- 숫자·날짜·고유명사는 **원 보도가 서로 다른 2건 이상**에서 같은 값이 나올 때만 쓴다.
  같은 통신사 기사를 받아 쓴 2건은 1건으로 친다. 1건뿐이면 그 1건이 1차 출처(정부·기업 발표, 원 보도)일 때만 쓴다.
- 출처끼리 숫자가 다르면(예: 88% vs 90%) 기준(기간·표본)을 문장에 밝히거나 보수적인 쪽을 쓴다. 애매하면 뺀다.
- 확인 못 한 운영 주체·배경 설명은 쓰지 않는다. "어제" 대신 "23일"처럼 **날짜로** 쓴다.
- WebFetch 가 막혀 기사 본문을 못 열면 검색 결과 요약만으로 판단하게 되므로 더더욱 교차 확인한다.
- **전망치 vs 실적**: 연휴·행사 '예상' 수치(예: 공항 이용객 전망)는 발행일에 실적이 나왔는지 다시 찾아보고,
  나왔으면 실적으로 바꾼다. 못 찾으면 문장에 '전망'임을 밝힌다.
- 실행일과 발행일이 다를 때(리허설·미리 만들기)는 본문의 시점 표현을 **발행일 기준**으로 쓴다(예: "연휴 뒤 첫 월요일").

### 1-4. 선정 기준 (10개 = 빅이슈 1 + 섹션 3×3)

1. 마케터가 **오늘 뭔가 해볼 수 있는** 이야기인가 (행동 가능성)
2. 숫자가 있는가 (카드·뉴스레터의 '큰 숫자' 재료)
3. `recent_item_titles` 와 겹치지 않는가 (같은 사건의 새 국면이면 OK, 그 점을 제목에 드러낸다)
4. 카테고리가 한쪽으로 쏠리지 않았는가 (섹션 3개가 서로 다른 축)
5. 빅이슈 = 오늘 가장 파급력 크고 숫자가 선명한 것

## 2. content/{날짜}.json 작성

예시는 **`content/2026-09-24.json`** — 이 파일과 같은 구조로 쓴다. 필드 요약:

| 필드 | 내용 |
|---|---|
| `date`, `emoji`, `title`, `hero_title`, `subtitle`, `cover_deck` | 제목은 질문·반전형으로 짧게, 쉼표로 호흡 (`토스가 이번엔, 새벽배송을 품었다고?`). `hero_title` 은 줄바꿈 `\n`, 강조 `==8월==` |
| `keywords` | 5개(manifest·아카이브용) |
| `source_mode` | `anjang` / `mixed` / `fallback` |
| `lead`, `three_lines`(사람들·돈·규칙), `observation` | 에디터 H 목소리 |
| `big_issue` | `tag`, `paragraphs`(2), `stat`, `takeaway`, `checklist`(1~3), `sources`, 카드용 `card_title`·`card_text`·`card_takeaway` |
| `sections` | 정확히 3개 × `items` 3개. 아이템: `tag`, `title`, `body`(2~3문장), `takeaway`(1문장), `sources`, 카드로 쓸 아이템만 `card` |
| `briefs` | 0~3개 짧은 소식 |
| `question` | `text`(강조 `==…==`, 줄바꿈 `\n`), `closing` |
| `instagram` | `caption`, `hashtags` (없으면 자동 생성) |

- 마크업: `**굵게**`, `==강조색==`, `\n` 줄바꿈. HTML 태그는 쓰지 않는다.
- 톤: "~했어요/~예요" 구어체 존댓말, 문장은 짧게. takeaway 는 **마케터가 무엇을 하면 되는지** 한 문장.
- 출처: `{"name": "매체명", "url": "기사 URL", "date": "MM.DD"}` — 날짜순으로 두면 마지막 날짜가 표시된다.
  `date` 는 확인한 경우에만 쓰고, 모르면 필드를 빼도 된다(추측해서 채우지 않는다).
- 카드뉴스 픽(5~7번 카드)은 기본값이 **섹션별 첫 아이템**이다. 다르게 하려면 `"card_picks": [3, 6, 9]`.
- 카드 글자 수 상한은 `automation/edith/content.py` 의 `CARD_LIMITS`. 넘으면 빌드가 무엇을 줄일지 알려준다.

## 3. 빌드

```bash
python3 automation/build_issue.py {날짜} --check   # 구조·글자 수 검증만
python3 automation/build_issue.py {날짜}           # 뉴스레터·카드·manifest·index 생성
```

- `✗` 메시지가 나오면 JSON 을 고치고 다시 실행한다. `↘ 자동 축소` 경고가 뜬 카드는 문장을 줄이는 게 좋다.
- 폰트는 처음 한 번 npm 에서 받아 `~/.cache/edit-h-fonts` 에 둔다(수 초).

## 4. 눈으로 검수 (생략 금지)

- Read 도구로 `instagram/{날짜}/*.png` **8장 모두** 본다: 글자 잘림·겹침, 어색한 줄바꿈, 오탈자, 숫자·단위.
- 뉴스레터: `node automation/preview_newsletter.cjs {날짜}.html <스크래치 폴더>/nl` 후 `<스크래치 폴더>/nl_*.png` 를 본다
  (두 번째 인자가 출력 경로 접두어. 세션에 스크래치 폴더가 있으면 그곳을, 없으면 `/tmp` 를 쓴다)
  (워드마크·카드 이미지는 배포 전이라 깨져 보이는 게 정상).
- 고칠 게 있으면 JSON 수정 → 3단계 재실행.

## 5. 커밋·푸시

```bash
git add {날짜}.html content/{날짜}.json instagram/{날짜}/ manifest.json index.html
git commit -m "Publish EDIT H {날짜} (VOL.{vol}) — {title}"
git push origin HEAD:main
```

- 푸시가 거절되면(non-fast-forward) `git pull --rebase origin main` 후 다시 푸시.
  네트워크 오류면 2·4·8·16초 간격으로 최대 4번 재시도.
- 이 5개 경로 외의 변경은 커밋하지 않는다. 파이프라인 코드 수정이 필요해 보이면 고치지 말고 보고에 적는다.

## 실패했을 때

- 10개를 채울 **검증된** 소식이 없으면 억지로 채우지 않는다. 빅이슈 1 + 확인된 아이템으로 9개 섹션을 못 채우면
  발행하지 말고 이유를 보고한다(빈 호가 틀린 호보다 낫다).
- WebSearch 자체가 안 되면 발행하지 않고 보고한다.
- 빌드 스크립트가 예외로 죽으면 에러 전문을 보고에 붙인다.
