## 7. RUNBOOK 에서 헷갈리거나 막힌 지점과 개선 제안

1. **대상 날짜와 실행일이 다를 때의 규칙이 없다.** RUNBOOK 은 실행일 = 발행일을 전제로 한다("최근 36시간", "어제 대신 23일").
   이번처럼 연휴 전에 미리 만들거나 연휴 뒤 첫 호를 만들 땐 ① 검색 기간 ② lead 의 시점 표현("연휴 뒤 첫 월요일")
   ③ 전망치가 발행일엔 실적으로 바뀌는 문제(공항 수치)를 어떻게 다룰지 한 단락이 있으면 좋겠다.
2. **긴 연휴 뒤 첫 호의 검색 기간.** 연휴(9/24~27) 중엔 기사가 적어서 36시간 창으로는 10개를 채우기 어렵다.
   "직전 영업일 이후 전체"처럼 바꾸는 규칙을 제안한다.
3. **0단계 `check_today.py` 에 날짜 인자를 넘길 수 있다는 설명이 없다.** 리허설·재빌드용으로 `check_today.py YYYY-MM-DD` 를 적어두면 좋겠다.
4. **소요 시간 측정.** 컨테이너 시계가 검색 대기 시간을 제대로 반영하지 않는 것으로 보인다(1번 표의 주의 참고).
   35분 제한을 지키려면 루틴이 시작 시각을 외부 기준(예: 커밋 시각, GitHub Actions 로그)으로 확인하는 방법이 필요하다.
5. **1-3 규칙의 '서로 다른 검색 결과 2건'** 이 "같은 통신사 기사를 받아쓴 2건"도 인정하는지 모호하다. 뮤즈 90만처럼
   원 보도가 하나인 수치는 결국 1건이다. "원 보도가 다른 2건"으로 명확히 하는 것을 제안한다.
6. **해외 1차 출처 표기.** Meta 뉴스룸·YouTube 블로그 같은 해외 기업 뉴스룸을 출처로 써도 되는지(1-2 목록엔 '기업 뉴스룸'만 있음),
   출처 `name` 을 어떻게 적을지 예시가 있으면 좋겠다.
7. **출처 `date` 는 선택 필드**인데(빌드가 검사하지 않음) RUNBOOK 은 필수처럼 적었다. 날짜를 모르면 비워도 되는지 적어두면 좋겠다.
